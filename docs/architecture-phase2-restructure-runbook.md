## Why this exists / what it is NOT

The repo already satisfies every **architectural invariant** the spec cares about:
DDD layer skeleton per service (`bootstrap/ domain/ application/ infrastructure/ interfaces/`),
one-writer-per-store, proto-first codegen, workspace_id 4-layer enforcement, money = integer
minor units, metric-registry TS↔Python parity. See `architecture-compliance.md`.

This runbook is **folder-shape alignment only** — renaming/relocating to the spec's exact
package + directory names. It has **zero functional value** and is exactly the work the spec
defers to the Phase-2 "mechanical split". Treat it as cosmetic hygiene, not a priority.

## Hard preconditions (do not start without these)

1. **Fresh branch** off the green tip: `git switch -c chore/arch-phase2-restructure <green-sha>`.
2. **CI green-gate per commit** — web tsc, gateway tsc, mobile tsc, web vitest, ingestion pytest,
   `pnpm install --frozen-lockfile`, `buf build protos`. No commit lands red.
3. **A stable shell** — the failures last time were tool-cancel cascades on `git mv`, not logic
   errors. If `git mv` / `pnpm install` get cancelled, STOP; do not hand-rewrite files from memory.
4. **Commit untracked-but-real files FIRST.** `connector_base.py` was untracked → a failed move
   deleted it unrecoverably. Run `git status` and `git add` every real source file before moving.
5. Work **one package / one sub-router at a time**; build-green + commit + push after each unit.

## Method that works (re-export shims)

For every extraction: create the new spec-named package with the REAL code, then leave a
**re-export shim** at the old path so the (dozens of) existing import sites keep compiling
unchanged. Verify green, commit. Flip call-sites to the new path later/optionally. Never rewrite
a moved file by hand — `git mv` then edit in place (read before edit).

## Phase E — context nesting + router split (HIGHEST risk; do LAST, optional)

Pure structure, the spec's deepest deviation, and the most breakage-prone. Two parts:

1. **Context nesting** — per backend service reshape `application/<feature>/` →
   `application/contexts/<bounded-context>/{domain,application,infrastructure,interfaces}`.
   Blast radius: hundreds of `git mv` + the `@brain/core-*` tsconfig aliases used by BOTH web and
   gateway + every internal import. Do ONE service at a time, ONE context at a time, build-green
   per move. The `@brain/core-*` path aliases are the seam that web depends on — update them in
   lockstep with each move.
2. **Router split** — `apps/api-gateway/src/application/router.ts` is one ~2,236-line
   `createBrainRouter(deps)` building a single `router({...})` (the `BrainRouter` type-seam the whole
   web app imports). Split into a `makeXxxRouter(deps)` factory per domain under
   `interfaces/trpc/`, with `router.ts` composing them and re-exporting `BrainRouter`. Preserve the
   exported type EXACTLY (it's the web app's entire type surface). Split one sub-router per commit,
   running `pnpm --filter @brain/web exec tsc --noEmit` after each (web type-checks the gateway router).

## Per-unit checklist (paste for each commit)

```
[ ] git status — every real file tracked (no untracked source about to be moved)
[ ] git mv (don't hand-recreate); read-before-edit any file you change
[ ] surgical package.json dep add (one line) + tsconfig path alias + buf/uv config if relevant
[ ] pnpm install  (or uv lock)  — must succeed
[ ] pnpm --filter @brain/web exec tsc --noEmit        → 0
[ ] pnpm --filter api-gateway exec tsc --noEmit       → 0
[ ] pnpm --filter @brain/mobile exec tsc --noEmit     → unchanged vs baseline
[ ] relevant tests green (vitest / pytest)
[ ] commit ONE unit; push; only then start the next
[ ] if any tool call is CANCELLED mid-op → STOP, re-verify state, do NOT proceed from memory
```

## Rollback recipe

Every phase is a clean ancestor chain, so `git reset --hard <last-green-sha>` + remove leftover
untracked dirs + `git checkout -- <restored tracked dirs>` + `git push --force-with-lease` fully
reverts. (This is exactly how the failed attempt was unwound to `23232e2`.)
